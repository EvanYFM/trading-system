# 研究工作站 V2 产品与部署方案

更新时间：2026-07-17

## 当前结论

- V2 先做静态、只读研究工作站，不立即购买云服务器。
- 当前日报 CSV、历史快照和静态页面可以直接部署到腾讯云 COS 或阿里云 OSS。
- 只有在加入账号权限、服务端定时抓取、数据库查询、私有数据或 API 代理后，才需要轻量应用服务器。
- 长图候选版已经合并到 `output/research_dashboard/index.html`，并将每日数据固化到 `output/research_dashboard/data/snapshots/YYYYMMDD.json`；`output/research_dashboard_v2_mockup/index.html` 仅保留为早期设计参考。
- 当前网页仍消费两份正式日报生成的 CSV。停用日报前，必须先把抓取、计算和质量校验抽成共享数据任务，再让网页直接消费共享 CSV/JSON；不能直接删除日报脚本或其数据目录。

## 品种详情信息架构

1. 顶部行情：板块、品种、主力合约、收盘价、涨跌幅、持仓量、数据日期。
2. 证据链摘要：行情结构、趋势温度、三方资金、席位结构、研究状态。
3. 价格与资金：同图观察价格、资金净变动、持仓边际及零轴。
4. 资金与席位：存量净持仓和今日边际分列，展示内资、外资、家人及净多/净空席位前五。
5. 趋势与周期：趋势温度、短中长周期信号、右侧天数和反转状态。
6. 基本面证据：按品种配置库存、基差、产量、消费、利润、仓单、天气等指标，并显示来源日期与历史分位。
7. 研报与事件：多空分歧、重要事件时间线，以及事实、策略判断、反向证据的分离展示。

## 从外部产品吸收的原则

- CTA 页面：先给市场状态和可执行关注项，再展开板块和品种证据；不复制已取消的散点共振地图。
- 奇货可查：品种详情采用持仓、行情、净持仓、持仓市值、结构、盈亏席位、基差、期限、仓单、库存、利润和研报等多入口，但 V2 将这些入口收敛为一条证据链。
- 交易可查：保留指数、商品、席位、深度分析和基本面的全局导航思路；品种详情以多空持仓、席位结构、库存和基差为核心。

## 部署阶段

### 阶段 A：静态评审版

- 本地构建 HTML/JSON/CSV，部署到 COS 或 OSS。
- 无登录、无服务端、无数据库；公开桶中不得包含账号、Cookie、API Key 或私有原始数据。
- 中国内地自定义域名需要备案；未备案时可先本地或临时测试地址评审。

### 阶段 B：个人在线工作站

- 使用 2 核 2 GB 轻量服务器，部署 Nginx、静态页面和只读 API。
- 定时任务在服务器生成快照，SQLite 或轻量数据库保存历史索引。
- 增加登录、访问日志、自动备份、HTTPS 和数据源失败降级。

### 阶段 C：多用户产品

- 前后端分离、数据库、对象存储、任务队列和权限系统。
- 增加品种订阅、提醒、回测、用户配置和数据授权审计。
- 进入该阶段前必须先确认数据源授权和商业使用边界。

## 第二阶段验收顺序

1. 已完成：长图总览接入真实快照，覆盖三方共振、资金潮汐、板块、趋势、核心品种、席位、天气、股指情绪和数据状态。
2. 已完成：用真实日报数据验证历史日期切换、品种详情、席位前五和资金零轴图。
3. 已完成：概念稿的信息架构已合并进主工作站“品种详情”，并由真实快照驱动；示意基本面和研报数字不进入主站。
4. 待用户评审：确认长图信息密度、模块顺序和单品种详情是否足以替代两份日报 HTML。
5. 待实施：抽取共享数据流水线，把“抓取与计算”从“报告渲染”中分离；网页构建只读取共享 CSV/JSON。
6. 连续观察 3 至 5 个交易日无缺失后，再停用两份日报 HTML，并决定静态托管或轻量服务器部署。
